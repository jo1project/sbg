# 手動測試情境

依 `docs/snake-battle-spec.md`（下稱「規格」）逐條寫的手動測試。每條規則至少一個情境；情境編號對應 `godot/PARITY.md` 的「驗證方式」欄。
同一份情境 Flutter 版和 Godot 版都要跑，結果要一樣——Flutter 的結果就是 Godot 的標準答案（兩者不同時先看 PARITY.md 文末「規格 vs Flutter 差異」）。

## 共通準備

1. **伺服器開除錯模式**（只在開發機！）：
   ```bash
   cd server && SBG_DEBUG_COMMANDS=1 npm start
   ```
   啟動訊息要出現「開發用除錯指令已啟用」。
2. **client 連本機伺服器**：Flutter 用 `--dart-define=SERVER_URL=ws://<電腦IP>:8080`；Godot 之後接上伺服器時用同一個網址。
3. **除錯面板**：Godot debug build 左上角「DBG」或按 F3。伺服器欄填同一個網址 → 連線 → 「重新整理」→ 目標玩家選要測的那位（面板上的指令都是針對這位玩家/他的房間/他的 NPC 對手）。
4. 下文的「**NPC 對局**」= 按隨機配對，等 8 秒自動配到 NPC。「**安靜 NPC**」= NPC 對局後在面板取消勾選「NPC 自動攻擊」，避免 NPC 自己亂打干擾時序（NPC 還是會自己吃食物加能量）。
5. 下文的除錯指令寫法：`能量(10)` = 面板「設定能量」填 10 按設定；`下次效果(暫停)`；`NPC閃避(永遠/永遠不/正常)`；`NPC攻擊(類型, 延遲ms, 能量)`；`NPC自動攻擊(關)`。
6. 需要兩個真人的情境用兩台裝置（或一台手機 + 一個電腦上的 client）。Godot 電腦版連線：
   `godot --path godot -- --online --sbg-server=ws://127.0.0.1:8080`；按「隨機配對」或 M；**F5 模擬切到背景 / 回到前景**。
7. **自動化測試**（伺服器端，用 WebSocket 模擬玩家）：`cd server && npm test` 一次跑完全部；
   單獨跑某一個：`node test/<腳本>.mjs`。沒設 `SERVER_URL` 會自己起一台測試伺服器（開除錯指令、暫存資料庫）；
   要測已經在跑的伺服器：`SERVER_URL=ws://127.0.0.1:8080 node test/<腳本>.mjs`（那台要 `SBG_DEBUG_COMMANDS=1`）。

數值（伺服器 `events.js` CONFIG）：能量上限 10、閃躲視窗 1000ms、預告 1000ms、防騷擾 3 次 / 暫停 3000ms、暫停效果上限 3000ms、食物 3 個、NPC 閃避 30%、雙殺窗口 200ms、NPC 補位 8000ms、邀請 30000ms、斷線寬限 10000ms、心跳逾時 5000ms、小地圖 2000ms（雜訊 -2～+2）。
移動：一般 350ms/格（Godot；Flutter 是 325ms）、加速 160ms/格；開局 4 節。
